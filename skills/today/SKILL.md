# /today — 每日开工（目标：5 分钟对话）

产出：更新后的看板 + 已派发的执行项。看板协议见全局 AGENTS.md，列标题必须逐字使用。

## 步骤

1. 读取（缺哪个就跳过哪个）：
   - `~/workspace/vault/plans/board.md`
   - `~/workspace/vault/reports/` 中最新一份报告
   - `~/workspace/vault/areas/okr/` 与最近一篇 weekly-review
2. 给用户一份 5 行以内的简报：昨日完成 / `👀 待我审` 卡片 / Backlog 中值得今天做的候选 2~4 条。
3. 与用户对话确定今日 2~3 件事；对话中出现的新想法先落成 `💡 Backlog` 卡。
4. 思考项（💭）：当场开始调研讨论；产出文档写 `work/<项目>/`；完成后卡片挂 `[[链接]]`。
5. 执行项（⚙️）：
   a. 任务卡在 `plans/tasks/`，按 `_template.md` 校验 repo/背景/目标/验收标准是否齐全；不齐先对话补齐。
   b. 齐 → 卡移入 `## 📋 Ready` → 派发 → 承接成立后卡移入 `## 🤖 Agent 进行中`，`status: running`，「执行记录」写派发时间、承接方与会话指针。
   c. 派发方式（**一卡一工作会话**，禁止本会话用子 agent 批量代办多张执行卡）：
      - 默认：为每张 ⚙️ 卡生成一条派发 prompt（必须含任务卡路径），用户复制到**新的** claude/codex 会话承接；只有新会话真正开工后才移卡到「进行中」。
      - 例外：本会话**最多自接一张**（通常是当天主线），自接即按协议登记会话指针，本会话从此就是这张卡的工作会话。
      - 说明：某张卡的工作会话内部用子 agent 并行搜索/干活属于实现细节，不违反一卡一会话——关联和回写始终落在该工作会话上。
6. 结束输出今日看板快照（各列卡片一行一条）。

## 约束

- 移卡 = 整行文本移动到目标 `##` 标题下；不改列名、不动无关卡片。
- 看板变更完成后在 vault 内 `git add plans && git commit -m "chore(board): today <日期>"`。
