# 处理点名给你的 Obsidian 批注

用户在 Obsidian 里用 Tandem Comments 插件给文档加批注。**没有任何机制会自动唤醒 agent**——这个 skill 就是那个扳机。用户写 `@claude` / `@codex` / `@kimi`（或 `@ai` 表示谁都行），你把点到自己的挑出来处理。

**批注的磁盘格式不在这里写。** 格式、锚点、修改建议、块的增删规则一律遵循 `obsidian-tandem-comments` skill（从 Tandem Comments 插件设置里导出，见 SETUP.md）。本 skill 只管外层工作流。

## 你是谁

`author` 一律写你自己的名字——`Claude`、`Codex`、`Kimi`。**绝不冒用别的 agent 的名字**：`scan.py` 靠 `author` 区分"已答复"和"待办"，署错名要么让你的工作被当成没做，要么让同一条批注被答两遍。

用 `--agent <名字>`（或环境变量 `COMMENTS_AGENT`）告诉 `scan.py` 查谁的队列。它默认查 `claude`，所以**你不是 Claude 的话，必须传 `--agent`**。

## 步骤

1. **扫描**：`python3 <skill 目录>/scan.py [路径] --agent <你>`。路径默认 `~/workspace/vault`，可传单个文件或文件夹缩小范围；`--all` 列出所有 agent 的队列。
   判定："状态 open" + "用户最后那条消息 @ 了你（或 @ai）" + "你在那之后没说过话"。

2. **先报告再动手**：列出找到了什么——文件、被批注的原文、用户的诉求。
   超过 3 条，或其中有需要用户拍板而非直接改的，**停在这里让用户挑**。别闷头改半个 vault。

3. **干活**：每条都先读一遍所在文档的上下文——批注是针对整篇文档的，光看被引用的那句话通常不够。
   然后回复；用户要求修改的，附上 `suggestion`。

4. **报告改了什么**：动过哪些文件，每条一行。没处理的说明为什么。

## 规则

- **绝不改正文。** 想改就写进 `suggestion.replacement`，由用户在 Obsidian 侧边栏点接受。这是整套设计的意义所在，不许抄近路。
- **不要替用户接受或拒绝修改建议**，除非本次对话里用户明确要求。
- **答完了不要顺手 resolve。** 在这个格式里 resolve 等于**删除**该条目——用户还没看见你的回复，批注就没了。resolve 只在用户明确要求时做。
- **别抢别人的活。** 点名给其他 agent 的线程不是你的，即使你答得了也别碰。`@ai` 才是先到先得。
- **时间戳必须跑 `date -u +%Y-%m-%dT%H:%M:%SZ` 取真值。** 凭感觉填的时间可能早于用户的提问，侧边栏排序会乱成"你先回答了还没被问出口的问题"。
- **Obsidian 可能正开着这个文件。** 一次写完，别留半截。
- 答在批注线程里，不要只答在聊天里——用户是回 Obsidian 看的。

## 范围

默认 `~/workspace/vault`。`plans/` 下是看板任务卡，那里的批注可能需要走看板协议（见 AGENTS.md），不是回一句就完事。
