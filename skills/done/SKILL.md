# /done — 收工回写

产出：任务卡执行记录更新 + 卡片移到 `## 👀 待我审` + vault 提交。看板协议见全局 AGENTS.md。

## 步骤

1. 确定本会话对应的任务卡（按顺序尝试）：
   a. 会话开头的派发 prompt 里含 `plans/tasks/` 路径 → 直接使用；
   b. 否则读 `~/workspace/vault/plans/board.md` 的 `## 🤖 Agent 进行中`，用本会话实际动过的 repo / 分支去匹配各卡的 frontmatter；
   c. 仍不确定 → 列出候选卡片让用户选；
   d. 确无对应卡但工作值得记录 → 询问用户是否按 `_template.md` 补一张卡再回写。
2. 回写任务卡：
   - 「执行记录」**追加**（不改写已有行）：完成时间、结果摘要 2~3 行、分支/PR 链接、遗留问题；
   - 若开工时未登记**会话指针**，补记一条（格式见 AGENTS.md 看板协议，用于日后 resume 回看对话）；
   - PR / issue 一律写**完整可点击的 URL**（markdown 链接，如 `[#8 0.1.1 bump](https://github.com/org/repo/pull/8)`），不要只写 `#8` 这类裸编号——任务卡会脱离会话上下文被回看；
   - frontmatter：`status: review`（需要用户决策的也是 review，把问题与选项写进执行记录）、补全 `branch` / `pr`（同样用完整 URL）。
3. 移卡：把对应卡整行从 `## 🤖 Agent 进行中` 移到 `## 👀 待我审`。
4. 提交：vault 内 `git add plans && git commit -m "chore(board): done <卡名>"`。
5. 如本会话有值得沉淀的讨论/决策，提醒用户可顺手 `/note`。

## 约束

- 一个会话对应多张卡时，逐卡执行 2~4。
- 只动本会话相关的卡；不改列名、不动他人卡片。
- 未完成也要回写（写清进展和卡点），不要静默留在「进行中」。
